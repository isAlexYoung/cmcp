# Claude MCP 中文桌面版

当前版本：3.3.3。保留逐台启停，增加桌面快捷方式提示，依赖版本不变。后续 UI 重构使用 4.x.x，本版不添加设置按钮。

## 文件布局

```text
Claude-MCP/
├─ Claude-MCP.exe
├─ app/       连接脚本、Node.js、node_modules、原有 BAT 入口和测试
├─ docs/      使用说明
└─ tools/     中文界面源码、编译与打包脚本
```

保留上述完整布局，EXE 会从 `app` 查找程序，从 `docs` 打开说明。个人设置和日志仍在原 LOCALAPPDATA 目录，不随目录整理移动。

## 使用

1. 完整解压便携 ZIP 到固定文件夹，保留 `app`、`docs`、`tools`。
2. 双击 **Claude-MCP.exe**，先看到“是否创建桌面快捷方式？”提示。“是”创建当前用户桌面的 `Claude-MCP` 快捷方式，“否”直接进入主界面。两种选择都可勾选“下次不再提示”；不勾选则下次仍询问。快捷方式使用随 EXE 内置的 Claude Desktop 图标，新电脑无需安装 Claude。打开管理界面不会自动登录、连接 VPS 或修改开机设置。
3. 第一次使用点击 **添加 / 修改**，按原向导保存云电脑地址。
4. **先选中列表中的一台云电脑，再点击启动连接**。只为这一台准备连接和配置，不重启其他连接。可以再选择第二台并启动，支持多台 VPS 同时连接这台 Windows 电脑。
5. 新版共享登录模式：选择列表中的云电脑，点击 **打开云电脑**，在浏览器中输入桌面密码。等待状态变成“已连接”；首次配置后，完全退出并重新打开云端 Claude。
6. 需要断开时选中对应行，点击 **停止连接** 并确认。只关闭这台的 MCP 通道和共享网页入口，另一台的登录、连接和工具调用继续运行。可以随时重新启动停止的这一台。

**关闭管理窗口会保留后台连接。** 启停开关按目标保存在本机；停止的目标在后台或 Windows 重启后仍保持停止。共享登录模式下，已启用目标重启后仍需通过“打开云电脑”网页登录。未选中目标时不能启停，A 的向导等待登录时仍可操作 B。

添加新地址不会自动启用它。修改现有地址保留该目标的启停开关。启动已经连接的目标不会重复登录；被其他电脑接管的目标可以通过手动启动重新连接。连接开关文件缺失或损坏时，新后台不会猜测要连接哪些目标。

管理界面中的停止不会移除共用的后台自启项，以免影响其他 VPS。所有目标停止后后台可以空闲运行；这不表示仍连接着 VPS。**原有 `app\Start-Claude-MCP.bat` 和 `app\Stop-Claude-MCP.bat` 保留明确的全部启动／全部停止语义**；逐台操作请使用 EXE。停止连接并不撤销已提交给 Windows 的文件写入，也不会统一结束已运行的本机程序。

快捷方式提示偏好保存在 `%LOCALAPPDATA%\ClaudeLocalMcp\manager-preferences.json`，与密码和连接配置分开。创建失败会提示且不会记住“是＋下次不再提示”，便于下次重试。已有本程序快捷方式可以更新到新位置；同名的其他快捷方式不会覆盖。快捷方式引用当前便携目录，创建后不要直接删除或移动该目录。暂未提供设置入口。

升级时若检测到不支持逐台控制的旧后台，程序明确拒绝自动接管。需要用户先用 `app\Stop-Claude-MCP.bat` 停止全部旧连接一次，再用新版 EXE 逐台启动；程序不会偷偷断开其他 VPS 完成升级。管理员权限不作为界面的默认要求。

## 权限与状态

- 继续使用当前 Windows 账户的文件、命令和桌面权限；这次界面封装没有缩小或扩大原有工具能力。
- 不在管理界面显示或保存密码、Cookie、Session、本机入口密钥。原后台设置继续保存在 `%LOCALAPPDATA%\ClaudeLocalMcp`，不要分享该目录。
- 每两秒读取本地状态，并核对每台的连接开关和操作版本；不会把上一轮连接状态误作新连接成功。后台 PID 不存在、已停止或状态超过 30 秒未更新时，不显示有效连接。
- 显示“已连接”表示后台已报告成功，管理界面不会为了刷新状态主动调用 VPS。
- 连接故障、授权失效及真实工具能否运行，仍由现有连接核心和 VPS 返回决定。

## 打包与兼容

适用原项目要求的 Windows 10/11 64 位环境，使用 Windows 自带 .NET Framework 4.x/Windows PowerShell 5.1，保留内置 Node.js。**不要只复制 EXE**：它是中文管理入口，运行仍需要旁边的完整程序文件。

EXE 尚未使用商业代码签名证书。Windows 下载保护可能提示未知发布者；发布前应独立核验 ZIP 哈希及来源，不建议关闭系统安全功能。

开发者可在本机重建：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build-manager.ps1`。

生成新的便携包：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\package-manager.ps1`。输出已存在时拒绝覆盖，需指定新输出目录；不会打包个人 LOCALAPPDATA 配置、状态、日志或凭据。

## 环境不足会自动下载吗？

**不会自动下载 Node.js，也不会自动运行 npm 安装。** 程序只使用 `app\runtime\node.exe` 与包内现有的 `app\node_modules`。缺失时连接向导报错，需重新完整解压便携包；不会改用系统 Node.js。

Windows 10/11 64 位、自带 Windows PowerShell 5.1 和 .NET Framework 4.x 是本机前提；不满足时不会自动安装系统组件。VPS 的 Python 3.9+ 也只检查、不自动安装。首次连接会上传自带 Python 连接器并注册 Claude MCP，这属于现有配置流程，不是联网下载依赖。

因此运行本工具不需要预先另外安装 Node.js，但“完整解压”和“自动修复缺失依赖”是两回事。

- Node：30 项通过，含原有 23 项认证、重连和兼容终端回归，以及新增的双目标连接、取消、协议探测／登录中断与真实后台子进程检查。
- 双目标测试使用两个独立的本机 HTTP/WebSocket 模拟桌面，验证 A 停止／重启后 B 的连接、Cookie+Session、网页入口和实际 MCP 工具请求均保持可用。模拟云端配置只返回测试结果，不执行远端 Shell。
- 没有连接真实 VPS，没有修改个人密码、目标开关或自启设置。真实 VPS 联机、用户已有生产状态及用户手动操作三项未执行，不能用本机测试替代。
